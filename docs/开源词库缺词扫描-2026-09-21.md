# 开源词库缺词扫描（2026-09-21）

## 结论

网上词库适合做「缺词发现器」，不适合不经对局直接并入出厂词库。本轮三源交叉得到 1,684 个青简缺词，其中 245 个在本地知乎验证语料中出现不少于 3 次。筛出 65 个高频且两套拼音一致的候选后，全量导入使无上下文首选从 `37/65` 降到 `36/65`，因此否决全量导入。

典型原因是同码冲突：「商朝」能从错误首选修好，但同时把原本正确的「上朝」压了下去；「呵呵」会被「赫赫」反超。青简原本的组句能力已经在不少「词库未收录」项上给出正确首选，不能把「没有独立词条」等同于「打不出来」。

## 数据源与准入

- Jieba `dict.txt`（MIT）：候选词与词频。
- Rime Essay `essay.txt`（LGPL-3.0）：独立词频信号。
- Rime Luna Pinyin（LGPL-3.0）：拼音候选。
- 青简基础词库、领域词库、品牌词全量去重。
- 本地知乎问题语料计数；拼音还需第二实现交叉校验。上游拼音本身存在「青青→jing jing」、「羧酸→zui suan」等错误。

## 可复现工具

`tools/corpus/collect_open_lexicons.py` 读取三个上游文件，输出待审核 TSV。它只做发现和语料计数，不修改产品词库。

```bash
python3 tools/corpus/collect_open_lexicons.py \
  --jieba /path/to/jieba/dict.txt \
  --essay /path/to/rime-essay/essay.txt \
  --luna /path/to/rime-luna-pinyin/luna_pinyin.dict.yaml \
  --corpus data/corpus/zhihu-q.txt \
  --min-corpus-count 3 \
  --output /tmp/qingjian-oov-candidates.tsv
```

## 后续准入规则

1. 候选必须在真实回放或冻结评测中暴露为错误，不以「词库不存在」单独判定。
2. 读音至少两源一致，涉及多音字时人工复核。
3. 每个新词必须对同码候选做回归；只接受净增益，不接受一换一。
4. 更适合从用户真实上屏中自动学习长词，公开词库只用来帮助确认这不是偶然拼接。
