现在继续提升，重点已经不是“再换模型”，而是让正确答案进入重排池、让模型获得更有效的上下文，以及减少错误学习。

我按收益潜力排序，建议关注下面 8 个维度。

## 优先级一：候选召回，而非候选排序

2B 模型只能重排 `paths=8` 里的候选。正确句子没进这 8 条，模型再强也无能为力。

当前分歧链主要能复活一次局部分歧，但以下情况仍容易漏掉：

- 两处同时发生同音分歧，例如两个位置都需要换成静态次优路径。
- 正确路径中途被束搜索剪掉。
- 正确词根本没进入某个词图格子。
- 简拼、纠错、切分歧义叠加。
- 低频长词被大量高频短词组合挤走。

建议实现“多样化 K-best 路径”，而不是简单把束宽或 paths 从 8 加回 16：

- 按切分结构、末词、分歧位置去重。
- 每种结构至少保留一条路径。
- 支持两处局部分歧组合。
- 用 lazy k-shortest/A* 从词图按需取路径。
- 只在模型不确定时扩展到 12/16 条。

核心指标应新增：

```text
oracle@8：正确句是否存在于前 8 条
oracle@16
重排后 top1
正确句首次出现名次
```

如果 `oracle@8` 只有 70%，就不该继续调模型；如果达到 95% 而 top1 低，才是排序问题。

这是我认为目前准确率潜力最大的方向。

## 优先级二：把全局 λ 改成条件化融合

现在基本是：

```text
最终分 = 静态分 + 0.75 × 神经修正
```

但不同情况不应该用同一个 0.75：

- 有完整应用前文和没有前文；
- 短句与长句；
- 精确全拼与简拼；
- 普通同音竞争与纠错路径；
- 有强个人证据与冷启动；
- 模型很确定与模型分差接近；
- 词级路径与多词整句路径。

可以先不训练复杂模型，只用一个很小的条件规则或线性校准器：

```text
λ = f(
  神经前两名分差,
  静态前两名分差,
  是否有应用上下文,
  候选长度,
  简拼比例,
  纠错次数,
  个人证据强度,
  候选切分差异
)
```

例如：

- 模型分差很小：降低 λ，保持稳定。
- 有可靠上下文、竞争集中在“的/得/地”：提高 λ。
- 候选包含敲错边：降低神经翻盘权限。
- 个人连续选过同一表达：提高个人证据保护。
- 冷启动长句：更多信任 2B。

相比继续扫一个全局 λ，这种“按情形融合”更有可能再取得稳定的 1–2 个百分点。

必须按天或按语域交叉验证，不能在同一份 895 主尺上同时训练和报告。

## 优先级三：个人学习系统升级

青简已有用户词频、个人 n-gram、自动造词和撤销学习，基础很好。下一步应从“累计次数”升级成“带置信度的在线学习”。

### 1. 利用负反馈

目前最有价值的信号不是用户选了什么，而是：

- 上屏后马上整段删除；
- 退格重打；
- 换选另一个候选；
- 连续翻页；
- 同一拼音第二次改成不同文字。

可以将这些视为负样本：

```text
第一次上屏 A → 很快删除 → 同拼音上屏 B
```

含义应是：

- 降低 A 在该拼音和上下文里的个人分；
- 提高 B；
- 如果 A 来自自动纠错，同时降低该纠错映射置信度。

这比单纯“选一次加一次”更接近用户真实意图。

### 2. 学习随时间衰减

永久累计会让几个月前的项目术语和口癖长期压住当前习惯。建议：

- 用户词频使用指数衰减或分层时间桶；
- 最近 7 天权重最高；
- 30–90 天逐渐回落；
- 明确添加的用户词不衰减；
- 错误学习和偶然选择衰减更快。

### 3. 按规范拼音泛化

TODO 里已经有一个明确机会：

> `wod` 下选择“我的”，目前惠及不到 `wode`。

建议学习键同时记录：

- 原始键串；
- 解析后的规范全拼；
- 候选对应的完整拼音；
- 双拼转换后的统一全拼。

查询时按置信度合并。这个改动成本不高，对简拼和双拼用户会很实用。

## 优先级四：上下文质量

现在使用光标前约 128 字，并支持右文，这是正确方向，但“截取最后 128 字”不是最有效的上下文选择方法。

建议改为结构化截取：

1. 优先保留当前句完整前文。
2. 再保留前一句末尾。
3. 识别换行、句号、问号等强边界。
4. 光标在句中编辑时，同时使用右侧当前句。
5. 不让代码、URL、日志长串挤掉最近的自然语言。
6. 应用取不到上下文时，明确降低神经权重，而不是把本地跨应用历史视为同等可靠上下文。

还可以增加轻量应用域特征：

- IDE/终端：技术词、英文尾词、路径和代码优先。
- 聊天工具：口语短语、语气词优先。
- 文档编辑器：正式书面表达优先。

不一定要把应用名喂给 Qwen；先用不同的静态 LM/领域词库混合权重就可以，而且隐私成本更低。

## 优先级五：改进模型前面的静态语言模型

2B 重排的前提是静态系统把好路径送进前 8。现在静态核心仍以 bigram 为主，个人三元又是近似状态，因此它更像“召回模型”而不是最终判别器。

可以考虑：

- 用 Kneser–Ney 平滑的三元模型替代或补充 bigram。
- 分成口语、技术、百科、文档四个子模型。
- 按应用类型和当前句特征动态混合。
- 用 2B 离线给大量候选对打分，把结果蒸馏成小型静态模型。
- 专门训练一个 20–100M 的中文同音判别器，而不是通用生成模型。

这里最值得尝试的是“2B 教师蒸馏”：

```text
大规模拼音句
→ 静态引擎产生混淆候选
→ 2B 对候选排序
→ 训练小型 pairwise reranker
```

它可以：

- 常驻更小；
- 更快地筛选到前 8；
- 让 2B 只处理困难样本；
- 专门学习“再/在、的/得/地、师/是、他/她”等输入法混淆。

## 优先级六：词库与新词发现

现有日志曾显示，很多词级 miss 本质上是缺词，不是排序错误。建议把新词管线自动化：

- 从 `retype`、翻页选择、连续分词上屏中挖 OOV。
- 区分真正的新词与偶然组合。
- 检测人名、产品名、技术术语、地点和缩写。
- 自动发现连续选择的 2–4 词短语，而不只合并两个词。
- 为用户词维护正确读音置信度，清理“我的 wo di”这种错误读音。
- 新词先进入个人词库观察区，多次确认后才升为稳定用户词。

评价不能只看词库覆盖率，应看：

```text
OOV 率
正确词 oracle 召回率
新词首次输入需要的按键/翻页数
错误自动造词率
```

## 优先级七：拼写纠错从固定规则变成噪声模型

当前一处编辑和个人敲错表已经有效，但固定代价无法区分：

- 相邻键误触；
- 音节边界错位；
- 高频个人错法；
- 双拼码位混淆；
- 连续快速输入造成的换位；
- 用户刻意输入英文。

建议从输入日志学习：

```text
P(实际敲入 | 目标拼音, 键盘布局, 输入方案)
```

然后做到：

- 每个用户有自己的混淆矩阵。
- 不同双拼方案使用不同错误模型。
- 高置信错误允许两处编辑。
- 低置信输入宁可原样保留。
- 纠错候选按总代价逐层展开，原始路径已经足够好时不再搜索低概率变体。

这一方向同时能提升准确度和性能，因为可以减少无意义的纠错枚举。

## 优先级八：性能从“固定 paths=8”升级为自适应预算

`paths=8` 已经很好地控制尾延迟，但所有句子统一用 8 条并不是最终形态。

建议做 deadline-aware 重排：

- 简单句：paths=2 或 4。
- 模型和静态首选一致且分差大：提前结束。
- 高歧义句：扩到 8。
- 只有 oracle 风险高且仍在时间预算内：扩到 12/16。
- 后台线程收到新按键立即取消旧请求。
- 根据用户真实敲键间隔动态设置防抖，不固定 80ms。
- 第一次激活输入法后低优先级预热模型和关键 Metal kernel。

目标不是降低平均 72ms，而是：

- 减少无意义的 GPU 唤醒；
- 降低功耗；
- 保住 P99；
- 困难句可以使用更多计算；
- 快速连续输入不做即将过期的推理。

## 建议补齐的评价体系

目前 top1、字准确率和回放已经很强，但下一阶段还需要把错误分层：

| 指标 | 回答的问题 |
|---|---|
| 词图 oracle | 正确词是否进入任何路径 |
| oracle@8 | 正确句是否送给 2B |
| reranker conversion | 进入前 8 后，2B 有多少翻到第一 |
| harmful flip rate | 2B 把原本正确的首选翻坏多少 |
| correction precision/recall | 纠错多少是真的，多少是误纠 |
| user effort | 每百字多选、翻页、退格、重打次数 |
| 分应用/分语域准确率 | 是否只在某类文本上涨 |
| P50/P95/P99 | 尾延迟是否失控 |
| GPU 唤醒与能耗 | 输入法是否持续耗电 |
| 学习半衰期 | 新习惯多久能学会、旧习惯多久能淡出 |

最终产品指标建议从“top1 准确率”升级为：

> 每千字需要用户纠正、翻页或重新输入的次数。

它比离线句子命中率更贴近输入法体验。

## 我建议的实施顺序

第一阶段，成本低、收益明确：

1. 给评测增加 `oracle@8/oracle@16` 和 harmful flip。
2. 规范拼音学习，让 `wod` 能泛化到 `wode`。
3. 将 retract/retype 转成明确负反馈。
4. 按句界选择上下文，而不是机械截取 128 字。

第二阶段，准确率主攻：

5. 多样化 K-best 与双分歧路径召回。
6. 条件化 λ/小型融合校准器。
7. 四域静态 LM 混合。
8. 自动 OOV 和用户短语发现。

第三阶段，性能和长期架构：

9. 自适应 paths 与提前退出。
10. 用 2B 蒸馏输入法专用小型召回/重排模型。
11. 带衰减、置信度和应用域的个人学习。

如果只选三个最值得马上立项的，我会选：

1. **候选 oracle 与多样化 K-best**——决定模型有没有机会选对。
2. **基于撤销/重打的正负个人学习**——直接利用真实用户反馈。
3. **条件化融合权重**——突破全局 `λ=0.75` 的上限。
